# Dormant provider inventory validation

`npm run infra:validate:providers` performs an offline, fail-closed inventory check for the exact ten entries in the mainnet planning directory. It requires one exact adapter, hostile-path spec, and research note for each of Aave, Morpho, Compound, Spark, Euler, Gearbox, Kamino, Save, Project 0/marginfi, and Jupiter.

The same command also validates the separate dormant mainnet financial-action boundary. Its domain contract pins the exact ten Ethereum/Solana provider-protocol-chain candidates and four dormant candidate actions, requires the fixed `DISABLED` policy with halted chain switches, empty approvals, zero limits, user-wallet-only signing/broadcast responsibility, and a denial-only result. The dedicated validator byte-pins owner-only migrations `0033` through `0042`, their focused and guarded PostgreSQL specifications, and the direct-import-only lifecycle, finality, signature-verification, recovery, and durable scheduler boundaries. The separate static inventory pins 42 recovery and scheduler artifacts. The exact migration-index contract registers `0033` through `0038` and rejects registration of `0039` through `0042`; all runtime grants remain absent. Mutation tests reject artifact drift, authority widening, unreviewed runtime composition, and unsafe lease/completion changes. Migration `0033` deliberately persists only `SUPPLY` and `WITHDRAW`; it requires append-only intent/event/evidence state, digest-only private evidence, canonical public chain transaction identity, and restart-safe post-bind reconciliation. Address-bound V2 in `0034` additionally requires the internally derived canonical Ethereum/Solana address HMAC candidates to equal the current accepted key policy and match the same account's `ACTIVE`, nonrevoked registered-wallet aliases before any lifecycle row can exist. The validator rejects V1 adapter fallback, caller-authored or logged candidate arrays, retries, extra database calls, runtime imports/exports, Nest registration, grants, I/O, dynamic code, transaction construction, and any signing, broadcast, or settlement authority. Commits `9af00ef`, `79c4b71`, and `51967aa` add and attest this boundary. This is a safety assertion only; it does not register or approve a provider, grant the adapter, or enable a mainnet write.

The validator reads repository files only. It has no endpoint, DNS, HTTP, provider SDK, credential, subprocess, chain, cloud, or write capability. Every consumed artifact is TypeScript or Markdown text; the validator does not consume a JSON inventory. The local reader requires a non-empty, canonical, single-link regular file inside the repository, reads the exact inspected byte count twice, compares nanosecond file identity and both byte snapshots, rejects a byte-order mark or malformed UTF-8, and emits only a fixed path-free error on failure.

Each artifact and runtime source file is capped at 2 MiB. The runtime scan is additionally capped at 4,096 files, 4,096 directories, 16,384 total directory entries, 64 levels, and 24 MiB of source. These bounds prevent an unexpectedly large source tree from turning the offline validation step into an unbounded read. Compiled runtime sources may use only the two exact reviewed literal dynamic imports; split/computed loaders and `require`/`eval`/`Function` loaders fail closed. The validator verifies that the planning directory remains `PLANNED`, `NOT_CONNECTED`, `UNAVAILABLE`, `NOT_ASSESSED`, action-free, and unable to authorize a financial action. Each reader must retain its explicit non-persistence, non-recommendation, and non-financial markers; Aave's older evidence contract has no persistence/recommendation capability and is checked for its explicit false financial-authority marker.

Five additional account-position semantics foundations are byte-pinned with their focused specs for Morpho, Euler, Gearbox, Save, and Project 0/marginfi. These pure, offline calculation boundaries must retain false persistence, completeness, and financial-action authority; remain bound to adversarial focused specs; avoid runtime I/O and adapter imports; and have no unreviewed reference from another compiled runtime source, including a `*.test.ts` barrel. The exact Gearbox transcript evaluator is the sole reviewed additional runtime source permitted to import Gearbox semantics, and its semantics and transcript specs are separately pinned; every other runtime reference fails closed. Any newly added `*-account-position.semantics.ts` file also fails closed until it is deliberately reviewed and added to the exact inventory. Jupiter is intentionally absent because its pinned public evidence cannot yet establish safe wallet-position semantics; its research note records that blocker instead.

Gearbox also has one separately bounded, pure account-position transcript evaluator from commit `5fcc7ca`, byte-pinned into this inventory by commit `040e93a`. It validates a caller-asserted exhaustive manager/account transcript that matches the caller-supplied approval list, fixed manifest and semantics fingerprints, caller-supplied topology/code approvals, gapless pagination, stable manager/account inventories, checked supply/debt arithmetic, and closed false-authority output without owning a transport, endpoint, clock, credential, database, or runtime registration. Its result deliberately reports completeness as `NOT_ESTABLISHED_PENDING_INDEPENDENT_AUTHENTICITY`. This evaluator is not a seventh complete provider-position source and is not included in the 45-artifact production-preflight provider slice; its dedicated inventory validator owns it.

Runtime source files are scanned for every exact adapter class/import stem and every inventoried semantics symbol/import stem. A reference outside the reviewed artifact itself fails validation, as does a Nest registration decorator. This intentionally prevents the static inventory from becoming runtime wiring through a module, barrel, CLI, controller, or other production source.

The [Aave read-only connection](../aave-readonly-integration.md) adds two exact,
separately byte-pinned private connection artifacts and their specifications:
the PostgreSQL wallet/checkpoint context reader and the bounded HTTPS RPC
transcript reader. Only those reviewed files may compose these components.
Missing or modified artifacts and references from any other compiled runtime
file fail validation. This exception supplies no endpoint configuration,
runtime registration, source approval, or live evidence.

Passing this validator proves only local artifact completeness and dormancy. It does not approve a provider, market, asset, endpoint, source pair, risk decision, recommendation, transaction, or production activation. Six provider-position sources are complete only as dormant local source artifacts; Gearbox remains an incomplete unauthenticated transcript boundary rather than source seven. All ten providers remain unavailable, with `liveReadEvidenceBound` and `transactionEvidenceBound` both 0 of 10.

The offline production preflight invokes both bounded validators and keeps their
results separate from each other and from KAN-62 decision-record validation. An
inventory failure makes `RPC_INDEXING` local validation fail with
`RPC_PROVIDER_DORMANT_INVENTORY_LOCAL_VALIDATION_FAILED`. An action-boundary
failure instead blocks `READ_ONLY_ISOLATION` and `MAINNET_WRITES` with
`MAINNET_ACTION_BOUNDARY_LOCAL_VALIDATION_FAILED`; it is never misreported as an
RPC inventory failure. This integration adds no network, provider, cloud,
secret, transaction, or filesystem-write action.
