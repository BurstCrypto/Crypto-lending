## Transcript guarantees and intentionally raw output

The reader selects an Ethereum `finalized` header and binds every `eth_getCode` and `eth_call` to [EIP-1898](https://eips.ethereum.org/EIPS/eip-1898) `{blockHash, requireCanonical:true}`. It rechecks chain ID plus the exact height/hash/parent/state-root/timestamp after all state reads. A caller-bound positive maximum block age is capped at 3,600 seconds; future blocks and the exclusive stale boundary fail closed.

At that one source point it verifies runtime code, AddressProvider-to-ContractsRegister resolution, `isPool(pool)`, the Pool's immutable AddressProvider and underlying token, ERC-4626 `asset()`, V3 version `300`, and pool/token decimals `6`. It exposes only the official interface's raw `availableLiquidity`, `expectedLiquidity`, ERC-20 share `totalSupply`, `supplyRate` ray, `paused`, and `totalDebtLimit` values. `totalDebtLimit` is a borrowing/debt cap, not a deposit cap. The adapter does not label the raw rate APR or APY, infer deposit availability, or treat an unpaused observation as an authorization.

All JSON and ABI values are bounded, accessor-free, exact-shape plain data. Amounts remain integers. Output is always `SINGLE_UNTRUSTED_RPC`, `NON_PERSISTABLE_PROVIDER_NATIVE_CANDIDATE`, no-recommendation, and no-financial-action.

Every path, byte length, and digest is executable data covered by the artifact's own domain-separated content fingerprint.

Direct wallet supply and credit-account debt are deliberately separate positions:

- Direct supply is the wallet's `balanceOf(wallet)` on the exact USDC PoolV3 diesel/ERC-4626 share token. A same-block wallet balance above `totalSupply` is impossible ERC-20 state and fails closed, so the PoolV3 `totalSupply == 0 ? shares : ...` branch can produce only zero for an observed wallet balance. Otherwise gross underlying is `floor(shares * totalAssets / totalSupply)`, matching PoolV3's `_convertToAssets` and OpenZeppelin's 512-bit `mulDiv` rounding down. An intermediate wider than 256 bits is valid, but a quotient wider than `uint256` fails closed. `previewRedeem` is, at most, a separate net-withdrawal estimate after the pool withdrawal fee. Wrapper/zapper/farm-held diesel shares, ordinary wallet USDC, and credit-account collateral are not attributed as direct wallet supply.
- Borrow is the checked sum of `debt + accruedInterest + accruedFees` returned by `CreditManagerV3.calcDebtAndCollateral(account, DEBT_ONLY)`. The returned accrued interest already incorporates cumulative quota interest. The transcript must cross-check the returned principal, prior index, enabled-token mask, and PoolQuotaKeeper against the same-block `creditAccountInfo` and topology values. `creditAccountInfo.debt` is principal only, not current total debt. `PoolV3.totalDebtLimit` and manager debt limits are protocol caps and must never be reported as wallet debt.

A future reader may report complete zero debt only after it takes durable authenticated wallet and continuity context first, then processes one bounded finalized EIP-1898 `{blockHash, requireCanonical:true}` transcript. It must enumerate the exact pool's entire `creditManagers()` set without filtering managers whose current debt limit is zero; for every manager it must verify version, pool, underlying, AddressProvider, AccountFactory, current facade and the facade's reverse manager link, plus the current PoolQuotaKeeper topology. It must enumerate gapless pages over the manager's full `creditAccountsLen()`, repeat the length, reject duplicates and bounds overflow, verify each active credit-account clone's manager/factory/version/runtime code, and use only the same-block `creditAccountInfo(account).borrower` for ownership because account addresses can be recycled after closure. Historical facade events cannot establish current ownership. Every wallet-owned account's `DEBT_ONLY` result participates in the checked aggregate; an unsupported manager or account invalidates the whole position instead of being skipped.

All topology, code, supply, borrower, and debt observations must bind the same EIP-1898 block hash, followed by an identical closeout header, chain-ID recheck, and continuity-floor check. The evaluator enforces that closed transcript shape, exact operation order, stable manager/account inventories, gapless pages, and caller-approved runtime-code and topology identities. These rules establish deterministic parsing and arithmetic only: the artifact is unregistered, performs no I/O, and keeps persistence, signing, financial-action, and complete-position authority false. A coherent response from one RPC is still not authenticated data or independent finality.
