# KAN-255 — Local managed-yield allocation previews

KAN-255 extends the authenticated, zero-egress demo after KAN-254. It changes
only the explicitly guarded local-demo composition; the production KAN-68,
KAN-69, and Smart Yield contracts remain unchanged.

## Product behavior

The idle portfolio reports current, supported, priced capital before a strategy
has been selected. With both fixture wallets, portfolio value and available
buying power are `$11,000.00`. Stale, unsupported, unpriced, and otherwise
ineligible balance sources cannot increase buying power. Allocation amounts,
managed rates, yield projections, and execution-cost treatment remain absent
until the user requests an allocation preview.

The authenticated `GET /api/v1/local-demo/yield-catalog` endpoint exposes only
the status of immutable, checked-in EVM and Solana managed-rate observations: a
product-owned identifier, the supported ecosystems, capture and stale
timestamps, freshness, non-executable use, and the fact that risk is not
assessed. Multiple underlying protocols remain server-confidential. Provider
identity, protocol identity, markets, exact source records, provenance, and
source endpoints are not returned to the browser. The runtime performs no live
provider request.

The composite snapshot is labeled `CURRENT` only until the earliest checked-in
component freshness boundary and `STALE` afterward. A stale snapshot remains
available for local testing but stays non-executable. It is neither a quote nor
an authorization.

## Plan selection and liquidity adjustment

The user starts from one of three deterministic presets:

| Preset         | Liquid reserve | Managed-yield target |
| -------------- | -------------: | -------------------: |
| More liquid    |            60% |                  40% |
| Balanced blend |            30% |                  70% |
| More yield     |            15% |                  85% |

The portfolio renders these as quick starting points. Selecting one sends the
closed preset identifier, its displayed liquid-reserve basis points, and the
exact displayed portfolio snapshot ID to
`POST /api/v1/local-demo/allocation-preview`. After the first preview, an
explicit slider lets the user choose a 0%–95% reserve in 5% display steps and
apply it to a recalculated preview. Moving the slider alone does not change the
applied result or move funds. The API accepts only an integer reserve from 0 to
9,500 basis points and rejects any other caller-authored economic field.

The snapshot ID prevents a wallet connect or disconnect race: a changed
portfolio returns a sanitized 409 and the browser refreshes instead of rendering
the stale preview. The server owns the authenticated account, portfolio capital,
managed rates, confidential source selection, allocation math, and fee
assumptions. The caller cannot send custom filters, rates, capital, fee inputs,
provider details, protocol details, market identifiers, or provenance.

If the confidential scenario cannot select a matching internal observation, the
API returns the typed `NO_MATCHING_YIELD_OPPORTUNITIES` 422 state with the
sanitized message that the managed strategy is unavailable. It neither falls
back to a different preset nor exposes the failed source criteria.

The response exposes `LIQUID_RESERVE` and `MANAGED_YIELD` plus provider-neutral
EVM/Solana source-capital and managed-composition totals. Percentage labels are
the user-selected target applied to capital remaining after modeled one-time
fees; integer-cent amounts are authoritative and reconcile exactly. Each
ecosystem covers its own modeled fees before its remaining capacity participates
in the managed blend. Capital is kept inside its source ecosystem, so the
portfolio can be projected as one blend without inventing a bridge. No
confidential position, venue, market, contract, mint, network ID, or per-position
rate crosses the browser boundary.

## Yield projection and modeled execution costs

The preview itself creates no executable route or transaction. Its local operation is
therefore exactly `$0.00` with status `NO_EXECUTION`, while public execution
remains `UNQUOTED`. Separately, it provides a non-quote modeled scenario so the
preview does not imply that a real allocation is free.

The modeled scenario itemizes five components from server-owned inputs: network
activation and position volume, required asset conversion, EVM-to-Solana
transfer, position size and utilization, and a fixed per-active-allocation
routing amount. The cross-ecosystem component is zero because the composition
keeps each wallet family assigned to its own ecosystem. It does not claim that
EVM network placement is bridge-free; all public execution remains unquoted. Each
variable component is rounded up to a whole cent. Their sum is
deducted from gross capital before the aggregate reserve and managed-yield
buckets are allocated and projected. The response identifies the model and
rounding/funding treatment; it does not claim these estimates are executable
public-chain quotes.

The server computes yield from the post-model-cost confidential positions and
their exact base-rate decimals, then exposes only the aggregate effective APY
in basis points and whole-cent annual projections. Reward or promotional rates
are not folded into the managed base rate. `projectedAnnualYieldAfterFeesUsdMinor`
is the projected annual yield less the modeled scenario total and can be
negative.

`firstPositiveDayAfterFees` is a projection metric, not an execution promise.
It is the first whole day on which straight-line projected yield exceeds the
modeled fees by at least one cent. The result distinguishes recovered within
the 365-day model horizon, no projected yield, and not recovered within that
horizon. A numbered day is returned only for the first case.

## Safety boundary

The rate status and allocation preview are in-memory, local-demo projections.
They create no user-authorized financial operation, quote, reservation, ledger
entry, public-chain transaction, live provider request, or persistent
allocation. Local fixture maintenance may create zero-gas transactions only on
the owned loopback EVM after a reset. Responses carry a non-executable use
marker and `mayAuthorizeFinancialAction: false`; the browser also states that
no user-authorized financial transaction was created.

The Solana wallet, native route, and lending positions are modeled fixtures; no
Solana validator, bridge, provider adapter, or transaction is contacted. The
managed rates are historical server-confidential observations, not live
rates, forecasts, guarantees, or recommendations. This demo does not complete
KAN-176, KAN-181, KAN-184, or KAN-185. Those tickets remain authoritative for
approved opportunity discovery, risk classification, production allocation
plans, and confirmation-bound execution.
