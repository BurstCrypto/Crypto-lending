# KAN-255 — Local provider snapshot allocation previews

KAN-255 extends the authenticated, zero-egress demo after KAN-254. It changes
only the explicitly guarded local-demo composition; the production KAN-68,
KAN-69, and Smart Yield contracts remain unchanged.

## Product behavior

The idle portfolio reports current, supported, priced capital before a strategy
has been selected. With both fixture wallets, portfolio value and available
buying power are `$11,000.00`. Stale, unsupported, unpriced, and otherwise
ineligible balance sources cannot increase buying power. Fee amounts,
deductions, net planned capital, and break-even timing remain absent until the
user requests an allocation preview.

The authenticated `GET /api/v1/local-demo/yield-catalog` endpoint returns an
immutable, checked-in capture of five USDC/USDT Morpho Blue markets on Ethereum
and Base. The capture came from the public Morpho GraphQL API on
2026-08-26 at 14:14:54 UTC. It stores the exact query, source and retrieval
timestamps, provider block identities, and recorded SHA-256 request/response
digests. The exact raw response was not retained, so its recorded digest is
capture metadata rather than independently reproducible repository evidence.
The application performs no live Morpho request.

Each opportunity keeps these provider observations separate:

- native base supply APY, which drives filtering, ranking, and projections;
- reward APR components, which are displayed but excluded from ranking and
  projections;
- the reported market borrow-interest fee rate, which is not presented as an
  entry, routing, or application fee;
- provider TVL, utilization, and available-to-borrow liquidity; and
- the provider observation time and bounded checked-in capture metadata.

Available-to-borrow is only an exit-liquidity proxy, not a withdrawal guarantee.
No market has a risk classification, eligibility approval, or execution
approval. The snapshot is labeled `CURRENT` until its checked-in 24-hour
freshness boundary and `STALE` afterward. A stale capture remains visible for
local testing but stays non-executable.

## Preset selection

The user can request one of three deterministic presets:

| Preset         | Liquid reserve | Provider-listed snapshot allocation |
| -------------- | -------------: | ----------------------------------: |
| More liquid    |            60% |                                 40% |
| Balanced blend |            30% |                                 70% |
| More yield     |            15% |                                 85% |

For every preset, the server ranks provider-listed snapshot markets by exact
base supply APY, then opportunity ID, retains at most three, and divides the
non-reserve target as evenly as integer basis points allow.

The portfolio intentionally renders only these three preset choices. Selecting
one sends its closed identifier to `POST /api/v1/local-demo/allocation-preview`.
The server owns the authenticated account, portfolio capital, provider rates,
snapshot matching, ranking, allocation math, and fee assumptions; the caller
cannot supply or override any of those values.

## Yield and fee-recovery estimate

Only after selection, the preview shows the chosen markets, base-rate weighted
APY, projected annual base yield, projected first-year growth after local action
costs, and the first whole day on which projected base yield exceeds those
costs by at least one cent.

The one-percent cost applied to non-reserve capital is explicitly a
`LOCAL_DEMO_ACTION_COST_ASSUMPTION`, not a Morpho quote or observed charge. It is
split into liquidity, conversion, slippage, network, and routing categories at
50/10/10/10/20. Integer-cent largest-remainder allocation keeps gross capital,
allocations, deductions, fees, and net planned capital exactly reconciled.

The projection uses net planned capital and disclosed 365-day straight-line
proration. Reward APR is not added to the result. All calculations use integer
arithmetic:

```text
effectiveApyBps =
  floor(sum(targetWeightBps * marketBaseApyBps) / 10,000)

annualYieldMinor =
  floor(netPlannedCapitalMinor * effectiveApyBps / 10,000)

firstNetPositiveDay =
  ceil((totalFeesMinor + 1) * 10,000 * 365
       / (netPlannedCapitalMinor * effectiveApyBps))
```

## Safety boundary

The catalog and preview are in-memory, local-demo projections. They create no
user-authorized financial operation, quote, reservation, ledger entry,
public-chain transaction, live provider request, or persistent allocation.
Local fixture maintenance may create zero-gas transactions only on the owned
loopback EVM after a reset. Responses carry a non-executable use marker and
`mayAuthorizeFinancialAction: false`; the browser also states that no
user-authorized financial transaction was created.

The real values are historical provider observations, not live rates,
forecasts, guarantees, or recommendations. This demo does not complete
KAN-176, KAN-181, KAN-184, or KAN-185. Those tickets remain authoritative for
approved opportunity discovery, risk classification, production allocation
plans, and confirmation-bound execution.
