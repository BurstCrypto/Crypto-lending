# KAN-255 — Local managed-yield allocation previews

KAN-255 extends the authenticated, zero-egress demo after KAN-254. It changes
only the explicitly guarded local-demo composition; the production KAN-68,
KAN-69, and Smart Yield contracts remain unchanged.

## Product behavior

The idle portfolio reports current, supported, priced capital before a strategy
has been selected. With both fixture wallets, portfolio value and available
buying power are `$11,000.00`. Stale, unsupported, unpriced, and otherwise
ineligible balance sources cannot increase buying power. Allocation amounts,
managed rates, yield projections, and execution-cost treatment remain absent
until the user requests an allocation preview.

The authenticated `GET /api/v1/local-demo/yield-catalog` endpoint exposes only
the status of immutable, checked-in EVM and Solana managed-rate observations: a
product-owned identifier, the supported ecosystems, capture and stale
timestamps, freshness, non-executable use, and the fact that risk is not
assessed. Multiple underlying protocols remain server-confidential. Provider
identity, protocol identity, markets, exact source records, provenance, and
source endpoints are not returned to the browser. The runtime performs no live
provider request.

Internally, provider snapshot v3 evaluates ten distinct private candidates from
immutable, point-in-time developer captures: seven EVM candidates and three
Solana candidates. The EVM set covers Morpho, Aave, Compound, Moonwell, Spark,
Venus, and Euler; the Solana set covers Kamino, Save, and the internally labeled
P0/marginfi candidate. Those names identify private fixture provenance, not
user-selectable products, and never cross the public DTO or browser boundary. A
separately researched Drift observation is excluded before ranking because the
observed market was paused and the observation was stale; it is not one of the
ten selectable candidates. Application managed-rate runtime reads only the
checked-in captures, performs zero external provider, public-RPC, validator,
bridge, or public-chain I/O, creates no transaction, and incurs no provider
request or on-chain execution cost.

The v3 composite uses conservative aggregate times. Its aggregate `capturedAt`
is the latest component capture time, when the complete candidate set first
exists, and its aggregate `staleAfter` is the earliest component stale boundary.
The public product-owned ID is `managed-rate-snapshot-v3`; it discloses only the
fixture generation, not its private providers.
For this capture those values are `2026-08-27T01:04:48.000Z` and
`2026-08-27T14:14:54.580Z`, respectively.
The complete snapshot is labeled `CURRENT` only inside that interval and
`STALE` as soon as any component reaches its boundary. An invalid or
non-overlapping interval fails closed. A stale snapshot remains available for
local testing but stays non-executable. It is neither a quote nor an
authorization.

## Plan selection and liquidity adjustment

The API retains three closed product-plan identifiers for compatibility, but the
local-demo web flow offers only `BALANCED`, labeled **Managed blend**. It starts
fully allocated to managed yield, with no liquid reserve held by default. The
legacy `MORE_LIQUID` and `MORE_YIELD` identifiers are not presented as choices
until they gain distinct server-owned strategy dimensions.

The portfolio renders this as one selectable starting point. A first selection
sends the closed preset identifier, a zero-basis-point liquid reserve, and the
exact displayed portfolio snapshot ID to
`POST /api/v1/local-demo/allocation-preview`. After the first preview, an
explicit slider lets the user choose a 0%-95% reserve in 5% display steps and
apply it to a recalculated preview. Moving the slider alone does not change the
applied result or move funds. The API accepts only an integer reserve
from 0 to 9,500 basis points and rejects any other caller-authored economic
field.

In the current local fixture, all three accepted identifiers have identical
economics for the same reserve. They must gain a distinct server-owned strategy
dimension before being represented as economically different plans.

The snapshot ID prevents a wallet connect or disconnect race: a changed
portfolio returns a sanitized 409 and the browser refreshes instead of rendering
the stale preview. The server owns the authenticated account, portfolio capital,
managed rates, confidential source selection, allocation math, and fee
assumptions. The caller cannot send custom filters, rates, capital, fee inputs,
provider details, protocol details, market identifiers, or provenance.

If the confidential scenario cannot select a matching internal observation, the
API returns the typed `NO_MATCHING_YIELD_OPPORTUNITIES` 422 state with the
sanitized message that the managed strategy is unavailable. It neither falls
back to a different preset nor exposes the failed source criteria.

The response exposes `LIQUID_RESERVE` and `MANAGED_YIELD` plus provider-neutral
EVM/Solana source-capital and managed-composition totals. Percentage labels are
the user-selected target applied to capital remaining after deducted modeled
costs and any retained rounding residual; integer-cent amounts are authoritative
and reconcile exactly. Each ecosystem covers its own deducted modeled costs and
retained residual before its remaining capacity participates in the managed
blend. Capital is kept inside its source ecosystem, so the
portfolio can be projected as one blend without inventing a bridge. No
confidential position, venue, market, contract, mint, network ID, or per-position
rate crosses the browser boundary.

Confidential opportunity selection is deterministic and distinct-provider
first. Its selection pass admits at most one opportunity from a provider and
stops after at most two opportunities for each ecosystem. This is a local
diversification heuristic, not a provider endorsement or risk classification.
The public response omits the selected-position count and never identifies
which provider supplied an observation. Internally, the ten private candidates
produce at most four selected positions when both ecosystems participate; they
are not ten simultaneous positions.

The default two-route split starts at 60/40, then caps each confidential
position at the lower of its captured TVL and available-liquidity proxy. Any
remainder is reassigned only within the same ecosystem and selected provider
set. If their combined captured capacity is insufficient, the preview fails
with the same sanitized unavailable-strategy state instead of over-allocating.
Selection and this capacity-aware rebalancing are in-memory calculations over
the local snapshot only; they do not persist an allocation or submit a
transaction.

## Yield projection and modeled execution costs

The preview itself creates no executable route or transaction. Its local operation is
therefore exactly `$0.00` with status `NO_EXECUTION`, while public execution
remains `UNQUOTED`. Separately, it provides a non-quote modeled scenario so the
preview does not imply that a real allocation is free.

The modeled scenario itemizes five components from server-owned inputs: network
activation and position volume, required asset conversion, EVM-to-Solana
transfer, position size and utilization, and the canonical platform-routing
fee. Until subscription entitlements are integrated, the server explicitly
uses the Free tier. A plan with multiple positions, a swap, a bridge, or another
material orchestration is charged 20 basis points of managed capital; only one
exact same-network, same-contract-or-mint direct settlement is classified
`DIRECT_COMPATIBLE` and charged zero. The canonical fee replaces the earlier
local-demo routing calculation rather than stacking with it. The cross-ecosystem component is zero
because the composition keeps each wallet family assigned to its own ecosystem.
It does not claim that EVM network placement is bridge-free; all public execution
remains unquoted. Network, conversion, and market-impact components round up to
a whole cent and are deducted from gross capital. The platform fee uses the
canonical rule's half-even atomic-unit rounding and retains its canonical
`ADDED_ON_TOP` funding treatment. The response separately reconciles deducted
costs, the added-on-top fee, total fees, and capital required including that fee.

At a cent-rounding discontinuity, the solver chooses the maximum feasible
allocation and can retain up to three cents outside the projection as
`retainedRoundingResidualUsdMinor`. This amount remains user capital, is not a
fee, and is excluded from after-fee yield and break-even fee totals. A larger
gap signals a route-topology or activation discontinuity and fails closed rather
than being mislabeled as rounding. The reconciliation is `gross capital =
capital included in projection + deducted costs + retained rounding residual`;
added-on-top capital required equals `gross capital + added-on-top fee`. The
response identifies the model, Free tier, server-derived route classification,
rule version, and rounding/funding treatment; it does not claim these estimates
are executable public-chain quotes.

Exact observations, including base supply APY decimals and capacity inputs,
remain server-private for ranking, selection, and capacity checks. Before the
projection crosses the public boundary, the exact position-weighted aggregate
APY is conservatively floored to a product-owned 25-basis-point bucket. The
public effective APY, whole-cent annual yield, after-fee yield, and
first-positive-day projection are all derived from that bucketed rate rather
than the exact private aggregate. Reward and promotional APR observations
remain separate private snapshot metadata where present; they are not included
in ranking, selection, aggregate APY, or projected yield.
`projectedAnnualYieldAfterFeesUsdMinor` is the conservative projected annual
yield less the modeled scenario total and can be negative.
Captured provider listing does not establish operability: deposit and
withdrawal availability were not verified, and provider and protocol risk
remains unassessed.

`firstPositiveDayAfterFees` is a projection metric, not an execution promise.
It is the first whole day on which straight-line projected yield exceeds the
modeled fees by at least one cent. The result distinguishes recovered within
the 365-day model horizon, no projected yield, and not recovered within that
horizon. A numbered day is returned only for the first case.

## Safety boundary

The rate status and allocation preview are in-memory, local-demo projections.
They create no user-authorized financial operation, quote, reservation, ledger
entry, public-chain transaction, live provider request, or persistent
allocation. Local fixture maintenance may create zero-gas transactions only on
the owned loopback EVM after a reset. Responses carry a non-executable use
marker and `mayAuthorizeFinancialAction: false`; the browser also states that
no user-authorized financial transaction was created.

The Solana wallet, native route, and lending positions are modeled fixtures; no
Solana validator, bridge, provider adapter, or transaction is contacted. The
managed rates are historical server-confidential observations, not live
rates, forecasts, guarantees, or recommendations. Provider diversity does not
mean that provider, asset, smart-contract, liquidity, operational, or
cross-chain risk has been assessed. This demo does not complete
KAN-176, KAN-181, KAN-184, or KAN-185. Those tickets remain authoritative for
approved opportunity discovery, risk classification, production allocation
plans, and confirmation-bound execution.
