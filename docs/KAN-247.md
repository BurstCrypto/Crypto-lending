# KAN-247: Real intent and quote log correlation

KAN-247 is started but cannot be completed honestly from the current `main`
tree. Its canonical producers are explicit Jira dependencies:

| Dependency | Required contract                                                                       | Current state on 2026-08-24                                                 |
| ---------- | --------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| KAN-217    | Versioned, server-validated Send/Invest/Earn intent and canonical intent ID             | `To Do`, unassigned; no intent application module exists in this repository |
| KAN-75     | Persisted quote lifecycle, ownership/fingerprint/TTL validation, and canonical quote ID | `To Do`, unassigned; no quote application module exists in this repository  |
| KAN-51     | Closed structured logger, correlation context, job envelope, and ledger trace           | Implemented on `main`; Jira remains `In Review`                             |

This branch is local-only. It does not invent temporary intent or quote domain
types, call a routing/provider service, deploy anything, or claim the required
real end-to-end trace.

## Completed independent safeguards

The existing HTTP boundary generates its own request/correlation root and does
not trust arbitrary request headers. KAN-247 adds explicit end-to-end evidence
that valid-looking `X-Intent-Id` and `X-Quote-Id` values supplied by a client do
not enter structured logs or the observability snapshot. This is intentionally
tested with canonical UUID-v4-shaped values so rejection is based on provenance,
not merely bad formatting.

`LoggingContext` already limits `intentId` and `quoteId` to canonical UUID v4
values and exposes only closed context fields. Focused tests now prove malformed
domain IDs are rejected before a context extension and do not partially mutate
the active context.

These safeguards establish only a trust boundary. A UUID-shaped value is not
thereby a verified intent or quote.

## Required application-owned binding points

When the dependency contracts land, correlation must be added at the narrowest
boundary that has verified both identity and ownership:

1. The authenticated intent command ignores any caller correlation, actor,
   intent-ID, and quote-ID headers or body fields. The API keeps its
   server-generated request root.
2. KAN-217 validates and persists the canonical intent. Only the returned
   application-owned `IntentId` may extend the active context with `intentId`.
   A rejected/unauthorized request must not bind an ID inferred from input.
3. KAN-75 loads or creates a quote under the verified intent/account relation,
   validates its fingerprint, provider/config version, and TTL, then binds the
   persisted application-owned `QuoteId`. Expired, foreign, stale, or malformed
   quote input must not become correlation metadata.
4. The service passes the same bounded context to the transactional job
   publisher. `JobEnvelope.correlation` already carries `intentId` and
   `quoteId`; it rejects unknown fields and requires canonical UUIDs.
5. The worker restores that durable context for diagnostics only. It must not
   use correlation metadata for authentication, authorization, ownership,
   routing, quote validity, or a financial decision.
6. Ledger work adds the actual transaction and committed journal/ledger-event
   identifiers only after the corresponding application/repository operation
   succeeds. Retry/redelivery retains the original request root and domain IDs.

Do not introduce a general `bindIds(record)` or caller-visible correlation map.
Each domain module should expose a typed, application-owned success result and
bind only its exact ID after authorization and persistence.

## Real trace fixture required after KAN-217 and KAN-75

The acceptance fixture must use the actual intent and quote services and their
local persistence adapters. Synthetic IDs passed directly to
`loggingContext.runWith` are insufficient.

The local flow should be:

```text
authenticated HTTP request
  -> canonical intent validation/persistence
  -> canonical quote creation/load and TTL/ownership validation
  -> ledger transaction/lifecycle operation
  -> transactional outbox row
  -> local SQS transport and worker handler
```

Capture the application-owned structured records at each hop and query them by
the response's server-generated request root. The fixture must prove:

- every applicable hop has the same root, actual persisted intent ID, actual
  persisted quote ID, and verified initiating account actor;
- transaction and ledger-event IDs appear only after their real records exist;
- timestamps are logger-generated canonical UTC values;
- a valid-looking spoofed intent/quote header and malformed body IDs are absent;
- a foreign account's real intent/quote IDs are rejected without being logged;
- the outbox body retains the real bounded context across retry/redelivery; and
- private-key, bearer/capability/idempotency-token, credential, and raw-signature
  canaries are absent from every captured line and job attribute.

Use the guarded local PostgreSQL/LocalStack fixture pattern from the KAN-51
ledger trace. No mainnet, provider, cloud, hosted-CI, or paid-service call is
needed or authorized.

## Integration review checklist

- [ ] KAN-217 exports the canonical intent ID/value type and successful
      application boundary used by the trace.
- [ ] KAN-75 exports the canonical quote ID/value type, ownership check, and
      stale/expiry behavior used by the trace.
- [ ] Neither endpoint accepts authoritative intent/quote correlation headers.
- [ ] IDs bind only after authorization plus successful load/create.
- [ ] The quote is demonstrably related to the bound intent and actor.
- [ ] Job, worker, transaction, and ledger-event hops retain the same root.
- [ ] Closed logger and envelope allowlists remain unchanged or receive an
      explicit security review for any required event.
- [ ] Real trace, spoofing, cross-account, malformed-ID, retry, and secret-canary
      tests pass locally.
