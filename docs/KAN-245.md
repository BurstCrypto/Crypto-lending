# KAN-245: Structured logging runtime hardening

KAN-245 closes the local application-owned logging gaps left by KAN-51 across
the API, outbox/SQS workers, wallet/provider failure paths, domain failures,
and the Next.js Node.js server runtime. This work is local-only: it does not
deploy, invoke AWS, create or query a log group, run hosted CI, contact a wallet
or RPC provider, or activate a paid observability service.

## Runtime boundary

API, worker, migration, and OpenAPI executables continue to use the KAN-51
structured logger and one-shot fatal process handler. Next.js now supplies an
`instrumentation.ts` boundary with two Node.js hooks:

- `register()` installs one process-wide `uncaughtException` and
  `unhandledRejection` handler, including across development module reloads;
- `onRequestError()` emits an application-owned `web.request.failed` record
  for a handled framework request failure.

The web boundary is deliberately Node-only. A source-policy test rejects an
application route that opts into the Edge runtime, where the Node process and
sink guarantees do not exist. A future Edge route requires a separately
reviewed transport and fatal-error contract before that policy can change.

The one-shot fatal handler emits at most one `process.fatal` record and exits
with status 1. It never serializes the rejection reason. Repeated fatal signals
cannot create repeated output or repeated exit calls.

## Web event contract

Web records use the same fixed schema metadata as API and worker records:

| Field           | Value or constraint                         |
| --------------- | ------------------------------------------- |
| `schemaVersion` | exactly `1`                                 |
| `timestamp`     | logger-owned canonical ISO 8601 UTC         |
| `level`         | closed severity enum                        |
| `service`       | exactly `crypto-lending`                    |
| `workload`      | exactly `web`                               |
| `environment`   | bounded lowercase runtime name or `unknown` |
| `event`         | one of the three reviewed web events below  |

The complete web event/field catalog is:

| Event                 | Level   | Required fields                                                         |
| --------------------- | ------- | ----------------------------------------------------------------------- |
| `web.runtime.started` | `info`  | `outcome=success`                                                       |
| `web.request.failed`  | `error` | `outcome=failure`, `errorCode`; optional reviewed `method` and route ID |
| `process.fatal`       | `fatal` | `outcome=failure`, closed `errorCode`                                   |

Request routes are not raw paths. Only the checked-in static route IDs are
eligible, and every query, dynamic suffix, or unknown route is omitted. The
request-error adapter reads only own data descriptors for `method` and
`routePath`; it never reads headers, raw path, error message, stack, digest,
cause, response, or provider payload. Accessors and proxies fail closed. Event
fields are projected from plain own data properties, and event/level/required
field mismatches produce no output.

Both serializers cap a physical record at 4,096 bytes and construct base
metadata themselves. Serialization, time-source, accessor, and sink failures
cannot change request behavior. Tests compare API and web output directly to
freeze the shared schema version, timestamp representation, severity, service,
and environment semantics.

## Adversarial error-path audit

The shared API fixture supplies syntactically representative canaries for:

- PEM private-key material;
- bearer and ledger-capability tokens;
- raw idempotency tokens;
- credential-bearing database URLs;
- valid-shaped raw wallet signatures; and
- nested raw provider error/response payloads.

The fixture is exercised through real application boundaries rather than only
through a pattern scrubber:

| Boundary        | Exercised failure                                                                                                              | Local evidence                                                                                     |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------- |
| API             | unhandled Nest controller/provider exception with secret headers, query, body, message, cause, code, credentials, and response | only `framework.error` and correlated `http.request.completed` approved fields are emitted         |
| Wallet/domain   | mapped `WalletRegistrationRejectedError` carrying adversarial properties and raw proof material                                | generic 401 plus one approved rejected request record                                              |
| Wallet/provider | unhandled provider-shaped exception from the wallet service port                                                               | generic 500 plus approved framework/request records                                                |
| Outbox worker   | SQS publish rejection containing the full adversarial graph                                                                    | retry/terminal durable state retains only the closed error code; logs retain approved job metadata |
| SQS worker      | handler rejection across retry and dead-letter attempts                                                                        | result, telemetry, and logs retain only closed classifications and approved correlation fields     |
| Web request     | Next.js request-error input containing raw path, headers, credentials, signature, and provider graph                           | one `web.request.failed` record with the closed method/route/error classification                  |
| Web fatal       | accessor-backed fatal reason followed by a second fatal signal                                                                 | one approved `process.fatal` record and one exit call, with zero accessor reads                    |

Every captured response, durable failure result, telemetry snapshot, and JSON
line used by these cases is checked against the prohibited literal values. The
security property comes from closed projection; literal absence assertions are
defense-in-depth evidence that the representative graphs never bypass it.

## Source policy

The API source-policy test now recursively covers application-owned API and web
TypeScript/TSX runtime sources. The web suite carries the same independent
check. They reject direct `console.*`, direct stdout/stderr writes, Nest logger
sinks, and noisy dotenv imports as applicable. They also require every API CLI
fatal boundary and both Next.js instrumentation hooks. Client modules may not
import the server logger.

Next.js itself can emit framework-owned build/start diagnostics outside this
application event catalog, and browser console behavior is not a server log
transport. Those are not accepted as application log sinks. All checked-in
application-owned runtime output remains behind the reviewed serializers.

Release-quality local checks remain `npm run lint`, `npm run typecheck`,
`npm run build`, `npm test`, `npm run test:e2e --workspace
@crypto-lending/api`, `npm run format:check`, and `git diff --check`. Database
and LocalStack integration suites are optional here because the new failure
evidence uses in-memory dependencies and loopback Nest servers only. Deployed
delivery, access control, KMS use, retention, incident search, and deletion
remain separately authorized non-production evidence; this ticket makes no
claim about them.
